# Right D435i optical orientation correction, 2026-10-08

The current real right-wrist image has the gripper toward the top. The simulator's original nominal sensor orientation put it toward the bottom. A diagnostic fit of twelve eligible measured-joint/PnP observations from `runs/wrist-calibration/20261008T235836.028874Z` indicates a 179.48596773966835-degree relative rotation, mainly about the color optical Z axis. The limited diagnostic fit did not converge and is not an accepted extrinsic estimate; it supports the gross orientation correction only.

`config/camera/right_fixed33_installation.json` now specifies `optical_axis_roll_deg: 180`. The geometric transform is `T_parent_from_optical_corrected = T_parent_from_optical_previous @ Rz(pi)`. This preserves the nominal RGB pupil and forward ray and reverses the optical X/Y basis. It is independent of the existing 180-degree flange-Z rotation that places the whole CAD mount outside the right arm. CAD attachment, fixed 33-degree pitch, housing collision box, and left D405 optics remain unchanged. Housing/pupil translation is still nominal and needs physical calibration. SDK images and corner coordinates are not flipped.

Since K's principal point is not precisely at the image center, an optical half-turn projects pixels to `(2*cx-u, 2*cy-v)`, not exactly `(width-1-u, height-1-v)`. Keeping all original poses brought some board corners below the required 35-pixel margin. The route was therefore retargeted toward `[640, 518.4]` pixels, on the side away from the now upper-image gripper. Maximum per-joint change from the previous nominal route was 6.937976416020217 degrees. All thirty views passed fresh ChArUco detection (at least twelve corners), with minimum image margin 47.76577428263647 pixels. All 12,737 geometric path samples passed with minimum modeled clearance 15.003696913006744 mm. These are geometric checks, not dynamic or real-robot qualification. All 198 calibration tests passed.

The [comparison](../artifacts/reference/right-wrist-optical-roll-20261008/real-vs-sim-roll.png) uses a captured real RGB image and the same measured arm/lift angles for both simulated hypotheses. It uses the diagnostic fitted board pose and nominal 80-mm-open simulated jaws. Its purpose is orientation comparison, not precise physical silhouette or camera-position validation.

The currently running session keeps its originally loaded targets and scene. The corrected default right-wrist plan applies on the next launch. Existing raw captures remain native RGB and can still be used for calibration. Neither the older candidate extrinsic nor production policy calibration was overwritten. The older 2026-10-06 candidate is close to the old nominal roll; it must not be described as validating this current mounting orientation.

Reproduction and the original assumptions are preserved in `artifacts/reference/right-wrist-optical-roll-20261008/`. `compare.py` uses the archived old plan; `retarget.py` rechecks the corrected route offline. The diagnostic fit and revalidation do not open camera or robot devices.
